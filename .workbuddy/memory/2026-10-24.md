## 修复 SsmsQuickTools VSIX 构建：`Microsoft.VsSDK.targets` 找不到

**症状**：`msbuild` 报 `The imported project "$(VSToolsPath)\VSSDK\Microsoft.VsSDK.targets" was not found`，
fallback 搜索路径为 `C:\Program Files (x86)\MSBuild\Microsoft\VisualStudio\v17.0`。

**定位（已核实）**：
- VSSDK workload 已装：`<VS>\MSBuild\Microsoft\VisualStudio\v17.0\VSSDK\Microsoft.VsSDK.targets` 及 BuildTasks 齐备。
- `Microsoft.VisualStudioVersion.v17.Common.props`（定义 `VSToolsPath`）由 VS 的 `Microsoft.Common.props`
  第 111 行导入，但条件仅 `'$(VisualStudioVersion)' == ''` → 实际为空时不定义。
- `VSToolsPath` 真正来源是 NuGet 包 `Microsoft.VSSDK.BuildTools` 的
  `build/Microsoft.VSSDK.BuildTools.props`（`<VSToolsPath>$(ThisPackageDirectory)\tools</VSToolsPath>`），
  而该 props 只经 `obj\*.nuget.g.props` 在 restore 之后才导入 → 干净 checkout 首次 `-t:Restore` 就炸（鸡生蛋问题）。
- 全局包目录在 `G:\nuget\packages`（非 `~/.nuget/packages`）。

**改动**：
- `SsmsQuickTools/SsmsQuickTools.csproj`：导入前显式解析 `VSToolsPath`（已有值优先 → `MSBuildExtensionsPath`
  → `MSBuildExtensionsPath32` → 由 `MSBuildBinPath` 上溯 3 层的 VS 实例路径），Import 改为 `Exists()` 守卫，
  新增 `EnsureVsSdkTargets` target（BeforeTargets=PrepareForBuild），缺失时直接 Error 而不是静默不产 .vsix。
- `CLAUDE.md`：Build 段落补充上述根因与解析链说明。

**验证**：`dotnet build --no-restore` 可正常求值并导入包内 targets（`VsSdkTargetsImported=true`）；
用 `-p:ImportProjectExtensionProps=false` 模拟未还原，得到新的清晰报错而非原始 import 报错。
未能在沙箱内运行 VS 的 msbuild.exe（被执行策略拦截），故「VS MSBuild 走 MSBuildExtensionsPath 分支」为静态推断。

**遗留**：本 checkout 的 `lib/ssms22.6/` 只有 README.md 与 _types2.txt，SSMS 引用 DLL 缺失，
因此本机编译必然报 CS0234/CS0246；与本次构建错误无关。

## 补齐 SSMS 引用程序集（解决 CS0234 / CS0246）

- `lib/ssms22.6/*.dll` 被 `.gitignore` 排除（第 15 行），README.md 说清来源与用途，但新 clone 无法编译。
- 本机 SSMS 为 **22.11.12315.225**，全盘搜不到 22.6.11806.211（`P:\github\sql-pilot\lib\Ssms22` 是 22.4，
  `ssms-snippet-expander` 是 22.1）。经用户确认先用 22.11 解锁：已复制 10 个 DLL 到 `lib/ssms22.6/`。
- 关键发现：SSMS 22.x 的 AssemblyVersion 跨小版本稳定 —— `22.200.0.0`（SqlWorkbench.Interfaces /
  SQLEditors / ObjectExplorer / GridControl）、`18.100.0.0`（SMO 系）、`6.0.0.0`（Microsoft.Data.SqlClient），
  22.4 与 22.11 副本完全一致。故「必须用 22.6」的真实理由是 **API 面**而非强名绑定。
- 新增 `lib/ssms22.6/_SOURCE.txt` 记录真实来源（22.11）与发布前须换回 22.6 的待办；
  `CLAUDE.md` 修正了「Committed DLLs」（实际被 ignore）并改写绑定/API 面说明。

**验证**：`dotnet build --no-restore -p:DeployExtension=false` → 0 error，产出
`bin/Debug/net48/SsmsQuickTools.vsix`(84KB) + pkgdef；`dotnet test` → 86 passed / 0 failed / 5 skipped。
注意：`dotnet build` 下 `DeployExtension=true` 会报 `VSIX deployment is not supported with 'dotnet build'`，
部署（写入 SSMS Exp hive）必须用 VS 的 msbuild。
