# Origen de estos binarios (provisorio)

Estos DLL **no** se commitean (`.gitignore`: `lib/ssms22.6/*.dll`). Ver `README.md` para el detalle de
que tipo sale de que DLL y por que no se redistribuyen.

## Estado actual

- Copiados el 2026-10-24 desde una instalacion local de **SSMS 22.11.12315.225**:
  `C:\Program Files\Microsoft SQL Server Management Studio 22\Release\Common7\IDE\`
  (y `...\Common7\IDE\Extensions\Application\` para `SQLEditors.dll`).
- La maquina no tenia a mano los binarios de **22.6.11806.211**, que es la version de referencia del
  proyecto (ver `CLAUDE.md`, "SSMS reference assemblies").

## Por que se acepto 22.11 mientras tanto

Las identidades de ensamblado son estables entre minors de SSMS 22, asi que el binding en runtime no
cambia (se compilo y se verifico con estas copias):

| Ensamblado | AssemblyVersion |
| --- | --- |
| `SqlWorkbench.Interfaces`, `SQLEditors`, `ObjectExplorer`, `Microsoft.SqlServer.GridControl` | `22.200.0.0` |
| `Microsoft.SqlServer.Smo`, `.ConnectionInfo`, `.ConnectionInfoExtended`, `.Management.Sdk.Sfc` | `18.100.0.0` |
| `Microsoft.Data.SqlClient` | `6.0.0.0` |

El riesgo que queda es de **superficie de API**, no de binding: compilando contra 22.11 se puede usar
por accidente un miembro que 22.6 no tiene, y eso recien explota en runtime en una instalacion 22.6
(`MissingMethodException` / `TypeLoadException`).
